## Obsidian 实机验收

使用 Obsidian 1.15.0 自带的[官方 CLI](https://obsidian.md/help/cli)进行测试。每次测试先校验 vault 的完整路径，只允许项目内 `.test-vault`。独立配置通过 `--user-data-dir` 指向项目内 `.test-profile`，没有向日常配置安装插件。

[实机测试脚本](../scripts/test-obsidian.py)及[原始结果](obsidian-test-results.json)已保留。脚本用于首次创建的测试夹具；其中 `2024-02.md` 必须尚不存在，以实际检查“缺失月份 → 确认创建”。脚本不会自行安装或启用插件。

8 项实机检查通过

1. 日期操作打开真实 `MarkdownView`，处于 source / Live Preview 模式，光标位于目标日期标题后的行。
2. 通过真实原生 Editor API 输入文字，`editor-change` 事件驱动日历自动刷新。
3. 创建缺失日期前显示明确按钮，确认后保留编辑缓冲区完整前缀，重复点击不重复追加。
4. 打开已有月份文件，文件内容逐字保持不变。
5. 浏览缺失月份不写文件，确认后创建 2024 年 2 月的 29 个日期分节，并打开 29 日。
6. 真实视图正确显示 2026 年 2 月的 28 天、12 月的 31 天及跨年月份。
7. 通过官方 `reload` 重载 Obsidian 窗口，独立日历标签页和所选的 2024-02 恢复成功。
8. Obsidian `dev:errors` 没有捕获到 JavaScript 错误。

另核验了真实 `MarkdownRenderer` 输出、任务框只读、配对行对齐，并截图检查深浅色。并排编辑截图中，右侧原生编辑器输入的一行文字已经出现在左侧日历。截图通过 Obsidian 官方开发命令的 CDP 当前渲染帧采集，没有使用图像生成或重绘。
